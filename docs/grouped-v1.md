## Правила

Первоначальный pack_context выбирает фрагменты и применяет прежний бюджет.
Затем фрагменты каждого исходного документа собираются в непрерывный блок.
Документы из каталога 20-products с одной темой в корневом заголовке помечаются
как продуктовые; остальные — как справочные или иные. Название блока берётся
из заголовка базы при запуске, продуктовых фактов в код не добавлено.

Продуктовые блоки идут первыми, в порядке первого появления в исходном контексте.
Справочные и иные документы идут после них, также в стабильном порядке.
Внутри блока сохраняется исходный относительный порядок выбранных разделов.
Каждый фрагмент сохраняет исходный путь, полный заголовок и весь текст дословно.
Начало и конец блока явно обозначены. Справочные разделы не приписываются продукту
по сходству слов; общие оговорки не превращаются в свойства конкретного продукта.
Если метки превысят прежний бюджет символов, возвращается исходное оформление
целиком. Фрагменты не обрезаются и не вытесняются ради заголовков.

Группировка выполняется по документу, а не по выведенной моделью сущности.
Несколько документов об одном продукте остаются отдельными блоками. Типы станций
внутри одного документа дополнительно не разделяются. Это сознательно узкий первый
кандидат. Он не исправляет факты, не извлекает отдельные числа, не добавляет
не найденные условия и не гарантирует правильность вывода модели.
Перестановка блоков может ухудшить использование важных справочных материалов;
неизменность состава сама по себе не доказывает улучшения качества.

## Проверка

`python -B -m unittest discover -s tests -p test_grouped_context.py -v`

6 тестов прошли. На 50 существующих вопросах (18 demo + 32 ранее использованных
holdout) по словарной выдаче: группировка применена в 50/50, выбранные фрагменты,
их тексты, dropped и лимит 40000 сохранены. Это проверка форматирования, не новое
независимое измерение retrieval/генерации. Проверены сравнение продуктов,
справочные и неизвестные источники, пустой контекст, резервное оформление при
тесном бюджете, один вызов генерации на законченный ответ и изоляция диалогов.

`python -B tools/check_grouped_context_submission.py`

Фактический ZIP прошёл parent/worker на 18 демовопросах с синтетическими
эмбеддингами и ответами, без сети. Гибридный этап включился, форматированные блоки
дошли до генерации, получен CSV с точными уникальными ID и колонками id,answer.
Время 1.516 с относится только к синтетическому прогону. В первой настройке теста
бюджет 120 секунд не позволил baseline включить эмбеддинги из-за его резерва;
проверка повторена с бюджетом 300 секунд. Код кандидата не менялся.
Реальные bge-m3/Qwen, качество ответов, Docker и балл не проверены.
