# Кандидат hybrid-v1

Основа context-v1 сохранена без изменения промпта, политики контекста и восстановления ответа. Единственное функциональное направление — поиск по смыслу вместе со словарным.

USE_HYBRID=1 по умолчанию; 0 возвращает словарный путь. EMB_MODEL из окружения, резервное имя baai/bge-m3 по примеру организаторов. Доступ через тот же URL, ключ и /embeddings. Документы (с полными заголовками) и уникальные вопросы (последняя реплика и до трех предыдущих пользовательских сообщений) векторизуются один раз пакетами по 16. Индекс в памяти, в ZIP данных нет. Ответы соседних тест-кейсов не используются.

На подготовку выделено не более 120 секунд и оставлен резерв 120 секунд до общего дедлайна. Если времени нет, этап пропускается. Невалидный ответ, недоступность сервиса или исчерпание времени возвращают исходный словарный поиск. Число измерений, конечность/норма векторов, индексы и полнота ответа проверяются. Кандидаты объединяются reciprocal rank fusion с одинаковыми весами и константой 60. На один вопрос дополнительных запросов при генерации нет: векторы подготовлены заранее. Реранкер не включается автоматически.

53 теста проходят. Дополнительно выполнен полный запуск на 18 демовопросах с синтетическими векторами и тестовыми ответами: 233 документа, 18 вопросов, валидный CSV. Это проверка интеграции, не качества bge-m3 или консультации. Реальных вызовов сервиса организаторов не было. Рост балла не подтвержден; стоимость и скорость настоящих эмбеддингов пока неизвестны. Векторный поиск может добавлять ложные совпадения, поэтому включен отдельным кандидатом.

Архив: dist/energytool-hybrid-v1.zip. Архив context-v1 сохранен без замены. Сравнивать результат именно с отправленным context-v1, а не только с исходными 0,49. Если гибридный этап на платформе отключится из-за ошибки, кандидат фактически использует словарный путь; сообщения hybrid_ready/hybrid_fallback позволяют это различить при доступности логов.
