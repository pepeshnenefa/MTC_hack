## Изменения

- null, отсутствие content/choices и повреждённый JSON ответа теперь попадают в одну ограниченную попытку восстановления финальной генерации. reasoning_content не используется вместо ответа. При повторном сбое сохраняется техническое сообщение, а не выдуманный ответ.
- Штатный финальный запрос и восстановление имеют роли system,user. Служебная проверка добавляется к исходным документам и диалогу в том же user-сообщении. При восстановлении уточнение краткости добавляется в системную инструкцию, новый user не создаётся.
- Первый этап: один HTTP-запрос без транспортных повторов, максимум 15 секунд вместо 25. При недостатке общего времени пропускается. Финальная генерация сохраняет ограниченные повторы; общий бюджет по умолчанию 18 минут. Для 401/403 после первого этапа бессмысленная финальная попытка не делается.
- Цитаты клиента проверяются именно по пользовательским репликам, а не всему диалогу. Это не гарантирует правильность выбора актуального факта или вывода: семантику всё ещё определяет модель.
- Сводка содержит complete/degraded и число ошибок по типам. Частичный сбой сохраняет код 0, чтобы не отбрасывать готовые ответы: это явно выбранный компромисс, не утверждение полного успеха. Все строки со сбоем и исчерпание дедлайна дают код 2. Ни логи, ни CSV не содержат ключи или скрытые рассуждения.

Не изменяли факты базы, критерии проверки и политику консультации. Не добавляли принудительный JSON-mode: поддержка реальным прокси неизвестна. Невалидный JSON планировщика по-прежнему вызывает безопасный переход к исходной генерации. Строгость цитат и лимит токенов могут снизить долю успешных планов — это ограничение, не устранённая гарантия качества.
