# Конкурсный ZIP и CSV

Контракт: technical-requirements.md. Для автоматической проверки загружаем ZIP кода; questions.csv и knowledge-base.zip предоставляет платформа. Веб-интерфейс этому этапу не нужен.

## Команды из корня проекта

1. python submission/solution.py --questions demo_questions.csv --kb Knowledge-base --validate-only
2. python -m unittest discover -s tests -v
3. python tools/build_submission.py
4. python tools/check_submission.py

Результат сборки: dist/energytool-submission.zip. В архиве ровно solution.py, batch_io.py, requirements.txt. Файлы в корне, без внешней папки. README, база, демовопросы, индексы, конфигурации и ключи не включаются. Проверяется размер до 128 МБ; SHA-256 сохранён в соседнем manifest.json, который не входит в ZIP.

Офлайн-проверка распаковывает только разрешённые файлы, создаёт локальные входные данные и подключает тестовый отвечающий код. Он остаётся вне сборки. Сеть в проверочном процессе заблокирована. Результат: work/offline-check/format-check.csv и format-check.json. Ответы помечены ТЕСТ ФОРМАТА — их не отправляют как реальные ответы модели.

## Проверки
Уникальные ID, сохранение порядка и ведущих нулей, UTF-8/BOM, кавычки/запятые и многострочные вопросы; пределы 9999/10000/10001 символов; ошибки отдельных строк и полная запись CSV; корневая структура ZIP и воспроизводимая сборка; модель из окружения, общая авторизация, ограниченные повторы и отказ от повтора 401; прекращение зависшей обработки по общему бюджету с сохранением готовых строк.

## Перед первым сабмитом
Улучшить и измерить покрытие поиска. Пересобирать ZIP после любых изменений исходников. Хранить хеш версии, время отправки МСК, результат и ошибки. До 5 попыток в день, сброс 00:00 МСК. Личный API-ключ не требуется: доступ обеспечивает платформа. Фактических отправок пока нет.
