## Алгоритм
Из переданной базы при запуске читаются документы и разделы. При явной теме вопроса/истории выбирается продукт по агрегированным оценкам первых трех найденных разделов каждого подходящего документа. Используется структура файлов продуктов 21–25 из предоставленного корпуса, без вложенных в код фактов или индексов. Смешанный запрос может выбрать второй продукт с другой темой. При отсутствии явной темы — прежний словарный поиск, без принудительного продукта.
Выбранные документы передаются целиком, с исходными заголовками; суммарный предел целостных материалов 29 000 символов. Если второй документ не помещается, добавляются до трех его найденных разделов. Затем до четырех наиболее релевантных справочных разделов из остальных документов. Если целостный документ не помещается или подходящего нет, используется прежний поиск. Окончательная упаковка по прежнему бюджету 40 000 символов с учетом заголовков/разделителей. Это символьный, а не точный токенный бюджет; более длинный вход может замедлить модель.

USE_HIERARCHY=1 по умолчанию; 0 отключает новую маршрутизацию. USE_HYBRID=0 по умолчанию; эксперимент не использует эмбеддинги и не требует их сервиса. Поддержка старого гибрида осталась в исходниках для совместимости, но не участвует при стандартных настройках кандидата. Не включать одновременно при сравнении на платформе.

## Итерации проверки
Первая реализация уверенно маршрутизировала некоторые общие вопросы не в тот продукт и теряла одну размеченную группу (32/33). Исправлено: маршрутизация только при явном направлении, иначе fallback. Справочные дополнения ограничены четырьмя вместо большого списка, чтобы не превращать документ в еще более шумный контекст.
На 18 демовопросах + 8 прежних дополнительных сценариях в фактической упаковке сохранены 33/33 группы. Максимальный контекст 28 363 символа, источники не отброшены бюджетом на этих примерах. Это проверка попадания текста, не доказательство правильного ответа LLM. Набор уже использовался в разработке.
Новые синтетические тесты проверяют конец целостного документа, отсутствие постороннего продукта, общую энергетику с fallback, два продукта, смену темы, ссылку на историю, слишком длинный документ, неизвестный запрос, Windows-пути и фактический вызов worker без эмбеддингов. Генерация в интеграционных тестах имитирована.
