## Что реализовано

- Один запрос той же генеративной модели из окружения. Анализатор видит только
  нумерованные пользовательские реплики; ответы ассистента исключены.
- JSON: goal, до шести актуальных facts и до одного дополнительного queries.
  Каждый факт содержит subject, field, value, turn, quote. Допустимые field:
  product, object, quantity, location, constraint, goal. Неизвестные факты пропускаются.
- Проверяются точное наличие цитаты в указанной реплике, значения и непустого
  имени объекта в цитате, типы, размеры, номера реплик и противоречащие значения
  одного поля одного объекта. При неоднозначности план полностью отклоняется.
- Первый поисковый запрос строится из goal и проверенных фактов. Второй —
  необязательный дополнительный запрос. Таким образом, поля реально влияют на поиск.
- По исходному вопросу всегда выполняется обычный поиск. До двух дополнительных
  фрагментов выбираются из top-3 каждого нового запроса, исключая уже вошедшие
  в исходный контекст. Продукт не используется как жёсткий фильтр.
- Дополнения помещаются после исходного контекста: до 6000 символов суммарно,
  общий предел 40000. Исходные фрагменты не вытесняются. Полный исходный диалог
  передаётся генератору; JSON/goal/facts не подаются ему как доказательства.
- Нет постоянного состояния: каждый независимый тест заново анализирует только
  свою историю. Глобальное хранилище, каталог сущностей и RRF не добавлялись.

## Ошибки, затраты и ограничения

Анализатор делает одну HTTP-попытку без повторов, socket timeout до 15 секунд,
резерв для основной генерации 30 секунд. При общем остатке менее 45 секунд,
отсутствии пользовательских реплик или входе длиннее 20000 символов анализ пропускается.
Пустой/оборванный ответ, ошибка JSON, непроверяемые факты или HTTP-сбой возвращают
обычный baseline-поиск. Общий deadline API не изменяется. Socket timeout не
гарантирует строгую длительность при медленной передаче тела; после ответа
проверяется длительность, общий процесс ограничен исходным parent/worker.

Обычно два запроса на вопрос; исходные повторы/восстановление генерации могут
увеличить число. Параметры прокси и имя модели — исключительно из окружения.
Опциональный baseline-реранкер остался выключенным по умолчанию; для изолированного
эксперимента не включать USE_RERANKER. Логи содержат только счётчики/статусы/время.

Проверка цитаты доказывает присутствие текста, но не правильное понимание его смысла,
актуальности, отрицания или связи с объектом. Это остаётся задачей модели.
Свободные goal/queries тоже могут быть ошибочными. Отсутствие вытеснения документов
не гарантирует отсутствие вреда от дополнительных источников. Сравнения с двумя
значениями без явно названных объектов могут отклоняться консервативной валидацией.
Детальные исправления и ссылки между репликами проверены только на уровне контракта,
а не реального извлечения Qwen. Прежняя обработка ошибок генерации сохранена со
своими ограничениями; этот эксперимент не является исправлением всего baseline.
