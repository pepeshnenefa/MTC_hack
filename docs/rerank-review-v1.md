## Поведение

1. Словарный поиск baseline формирует пул, обычно 36 разделов.
2. POST /rerank оценивает документы с заголовками и именами источников.
   Три первых словарных результата сохраняют позиции; за ними идут результаты
   реранкера (обычно до шести), затем остаток первоначального пула.
   Индексы должны быть уникальными целыми числами в диапазоне. При ошибке
   сохраняется исходный порядок. Полный пул доступен сборщику оговорок, но
   не гарантируется включение каждого раздела в конечный контекст.
3. Неизменённый pack_context выбирает основные разделы и дополнительные условия.
4. Первая генерация получает исходный SYSTEM, контекст и полный исходный диалог.
5. Один редактор получает тот же контекст, диалог и черновик. Инструкция требует
   исправлять фактические ошибки, числа, смешение продуктов и пропущенные условия,
   сохраняя верные детали. Черновик не считается доказательством. Возвращается
   только окончательный ответ, без отчёта редактора.
6. Пустой, некорректный, слишком длинный, оборванный ответ редактора или ошибка
   запроса сохраняют черновик. При исходном обрыве вместо редактирования выполняется
   одна короткая повторная генерация без черновика. Третьей генерации нет.

Редактор — та же генеративная модель из окружения; отдельный ключ не нужен.
Семантическая правильность редакции программно не гарантируется: редактор может
ошибиться, удалить полезную деталь или добавить неподтверждённое утверждение.
Это гипотеза качества, а не доказанное исправление каждого ответа.

## Время и настройки

- `USE_RERANKER=0` отключает реранкер; по умолчанию включён.
- `USE_ANSWER_REVIEW=0` отключает редактор; по умолчанию включён. Восстановление
  пустого/оборванного ответа остаётся доступным.
- `RERANKER_MODEL` переопределяет `qwen/qwen3-reranker-8b` из примера организатора.
  Наличие этого имени на реальном прокси не проверено. Генеративное имя только из окружения.
- `RERANKER_TOP_N` обычно 6, `TOP_K` обычно 12; исходная валидация настроек сохранена.
- Один запрос реранкера без повторов: socket timeout до 10 секунд, резерв 35 секунд.
  При остатке общего времени менее 45 секунд этап пропускается.
- Один запрос редактора/восстановления без повторов: socket timeout до 25 секунд,
  резерв 3 секунды; при остатке менее 15 секунд этап пропускается.
- Socket timeout не является строгим общим дедлайном при медленной передаче тела;
  после получения ответа проверяется длительность, а весь worker ограничен
  исходным родительским процессом. Общий deadline не меняется между потоками.
- Обычно три HTTP-запроса на вопрос: реранкер, генерация, редактор. Транспортные
  повторы основной генерации могут увеличить число запросов. Это дороже baseline.
- Логи содержат этапы, статусы, длительности и количества, без ключей и диалогов.
