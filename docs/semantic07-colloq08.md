## Применяется ли 0.8

- `W_COLLOQUIAL` читается в одном месте — `retrieval.Search._query`. Вес разговорных замен
  (`крыша → кровля`, `электричество/свет → электроэнергия`, `завод → промышленное предприятие` и др.)
  становится 0.8 вместо 0.5. Набор слов запроса не меняется, меняются только веса.
- При пустом окружении `config.reload()` в архиве даёт 0.8 (в оригинале 0.5).
- Переопределить значение может только переменная `ET_W_COLLOQUIAL`. Устаревшего синонима нет:
  `W_COLLOQUIAL=0.2` без префикса игнорируется. Вызовов `config.override` в коде архива нет.
  В окружении сессии и прогона переменных `ET_*` не было. `tools/local_eval.py` передаёт только
  PATH/HOME/TMPDIR/LANG/LC_ALL и переменные LLM.
- Через настоящую точку входа (`solution.py --retrieval-report`, словарный поиск):
  - словарные оценки отличаются от оригинала в 6 вопросах из 18;
  - с `ET_W_COLLOQUIAL=0.5` отчёт варианта побайтно совпал с оригиналом, то есть кроме этого
    числа ничего не изменилось.
- В реальном прогоне с генерацией разделы в трассировке совпали с офлайн-выгрузкой при 0.8
  в 18 вопросах из 18. В 5 вопросах они отличаются от выгрузки при 0.5.
