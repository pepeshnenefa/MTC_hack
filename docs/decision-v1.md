# Конкурсный эксперимент: проверка условий перед ответом

Интервью завершено 2026-11-10. Пользователь подтвердил: два этапа для всех вопросов; бюджет по умолчанию 18 минут; при недостатке критических данных уточнять до окончательной рекомендации, но сообщать подтверждённые общие факты сразу. Нет доступа к реальной генерации вне конкурса, ответов и логов платформа не предоставляет. Доступен только общий балл.

## Порядок отправок

1. `dist/energytool-hierarchy-v1.zip` — существующий неизменённый архив, ещё не отправлялся по сообщению пользователя. Сравниваем с 53.028 у context-v1.
2. После результата выбираем ОДИН архив:
   - если hierarchy лучше: `dist/energytool-hierarchy-decision-v1.zip`;
   - если context остаётся лучшим (включая равенство): `dist/energytool-context-decision-v1.zip`.

Единичные баллы не позволяют исключить разброс судьи. Архивы второй попытки заранее подготовлены, но не отправлены. SHA-256 и состав рядом в *.manifest.json. Никакие данные, тесты, индексы или секреты в ZIP не добавлены.

## Изменение

Первый вызов той же модели проверяет до пяти условий: выполнено / нарушено / неизвестно, приводит дословные выдержки и предлагает действие. JSON проверяется на структуру и наличие цитат в исходных документах/диалоге. Это не доказывает логическую правильность вывода или принадлежность реплики клиенту: второй этап обязан сверить их с исходниками.

Второй вызов получает исходный системный промпт, уточнённую политику рекомендаций, неизменённые документы и диалог, а также служебную проверку как недоверенные данные. Выдаёт обычный ответ. Сравнение измеряет совокупность дополнительного этапа и необходимой инструкции его использования, не отдельный эффект JSON.

Первому этапу выделено максимум 25 секунд, оставляется не менее 12 секунд общего бюджета для ответа. При остатке менее 20 секунд этап пропускается; при невалидном JSON, неподтверждённых цитатах, обрыве или ошибке выполняется исходная генерация. Это инженерный резервный путь, а не требование регламента. Общий дедлайн и ограниченные транспортные повторы наследуются от выбранного baseline. Нормальный путь — два логических вызова; транспортные повторы и прежнее восстановление обрыва могут увеличить число запросов.

Служебные данные создаются заново для каждого вопроса; общий объект API не изменяется. Эталонные ответы не участвуют ни в одном этапе. Рабочий submission/solution.py не переключён автоматически; кандидаты собирает tools/build_decision_submission.py из точных сохранённых ZIP.

## Проверки и ограничения

Автотесты проверяют сохранность исходного контекста, отсутствие изменения общего дедлайна, отказ от выдуманной цитаты, резервный путь при обрыве/тайм-ауте и пропуск при нехватке времени. Оба распакованных кандидата обработали 20 вопросов decision-v1 через настоящий конвейер с синтетическим транспортом: 40 логических вызовов на каждый архив, полный CSV.

Реальные модель, задержка, частота валидного JSON и качество ответов не измерены. 20 локальных сценариев не передаются платформе: она предоставляет собственный скрытый набор. Не записывать синтетические результаты как оценки качества.

Полный локальный набор: 75 тестов прошли, включая четыре новых проверки двухэтапного кандидата. Это техническая проверка, не балл генерации.
