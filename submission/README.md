# Конкурсный CSV-скрипт МТС Energytool

Контракт сверён с docs/source/Технический регламент_МТС.md. Работает на стандартной библиотеке Python; установка сторонних пакетов не нужна. Этот README хранится в проекте, в конкурсный ZIP не входит.

## Запуск

На платформе: python solution.py

Платформа предоставляет DATA_DIR/questions.csv и knowledge-base.zip. Поддерживаются альтернативные имена из шаблона. По умолчанию DATA_DIR=data. Локально --questions и --kb позволяют указать CSV и архив либо папку базы.
Выход: submission.csv в рабочем каталоге, ровно id,answer, UTF-8. Порядок и текст ID сохраняются; пустые и повторяющиеся ID отклоняются. Ответы непустые, нормализуются в одну строку и ограничены 10 000 символами. Ответ сверх лимита заменяется техническим сообщением и учитывается как ошибка, а не молча обрезается.

## Конфигурация

Адрес LLM_BASE_URL или OPENAI_BASE_URL (также поддерживается BASE_URL из шаблона); ключ LLM_API_KEY или OPENAI_API_KEY; модель LLM_MODEL, OPENAI_MODEL или GEN_MODEL. У модели нет фиксированного резервного имени. Все три значения предоставляет платформа; личный ключ пользователя не нужен.
Один URL и один ключ для генерации и необязательного реранкера. Отдельный RERANKER_API_KEY не используется.
TEMPERATURE по умолчанию 0 (0–2); MAX_TOKENS по умолчанию 2048; MAX_WORKERS по умолчанию 3 (1–8); TOP_K по умолчанию 12 (1–100). Невалидные значения приводят к ошибке конфигурации. Число CPU не является квотой параллельных запросов.
USE_RERANKER=1 включает реранкер и требует RERANKER_MODEL из окружения. RERANKER_TOP_N по умолчанию 6 (1–100). Реранкер необязателен; при его ошибке сохраняется исходный порядок источников.
EMB_MODEL и CHUNKER пока не используются: эмбеддинги не реализованы, разбиение фиксированное по Markdown-разделам. PYTHONPATH обрабатывается Python.

## Время и сохранение прогресса

RUN_BUDGET_SECONDS — внутренняя настройка приложения, не переменная регламента: по умолчанию 1080 секунд (18 минут), допустимо 1–1140. Оставлен запас до 20 минут платформы.
Главный процесс создаёт полный CSV с временными техническими ответами и запускает отдельный рабочий процесс. После каждого результата рабочий процесс атомарно обновляет CSV. Таймауты HTTP и паузы повторов ограничены оставшимся бюджетом. 429/408/5xx и сетевые ошибки повторяются до трех попыток, 401 не повторяется.
По дедлайну главный процесс завершает рабочий, включая зависшие потоки; готовые ответы сохраняются. Незавершенные строки остаются техническими сообщениями, а не выдаются за успешную генерацию. Процесс возвращает код 2 при дедлайне или ошибке всех заданий; 1 при прочей ошибке; 0 при завершении с хотя бы одним успешным ответом либо пустым входом. Частичные ошибки отражаются в статистике. Принятие результатов аварийного запуска платформой не проверено.
Невалидный вход/конфигурация не создают новый результат. Существующий CSV после такого сбоя нельзя считать результатом нового запуска. В логах не печатаются ключи, вопросы, ответы или тексты исключений провайдера.

## Офлайн-проверки

python solution.py --questions PATH --kb PATH --validate-only
python solution.py --questions PATH --kb PATH --retrieval-report REPORT.json

Эти режимы не требуют модели и сети. Отчёт источников содержит материалы кейса и не должен публиковаться.

## Состояние

CSV-контракт, корневые модули, ошибки прокси и завершение по дедлайну проверены локально. Поиск — локальный BM25-подобный по Markdown-разделам с учётом контекста диалога, категории запроса, условий применимости и разнообразия источников (без эмбеддингов). Проверен на 26 размеченных сценариях: полное покрытие требуемых источников в top-12 — 26/26 против 24/26 ранее. Это метрика поиска, не качества ответов LLM или балл платформы. Качество генерации и запуск на платформе не проверены. Реальная генерация и запуск на платформе не проверены. Тестовые ответы в офлайн-прогоне не являются ответами для оценки.

## Кандидат context-v1
Добавлен context.py. Поиск берет расширенный пул кандидатов (не более 100), число основных источников задаёт TOP_K (по умолчанию 12). Квота на файл убрана; удаляются только повторы одинакового текста/слов в контексте одного продукта. Первые три источника сохраняют приоритет; до двух найденных релевантных разделов ограничений добавляются без вытеснения основных источников (до TOP_K+2). Полные заголовки сохраняются. Выход за бюджет 40 000 символов отражается безопасным счетчиком; это не гарантия токенного лимита модели.
При finish_reason=length или пустом финальном тексте — не более одной логической повторной генерации краткого ответа при запасе времени не менее 12 секунд. Используются исходные документы; незаконченный черновик не передается как факт. MAX_TOKENS не повышается. Неудачная или повторно оборванная генерация не вытесняет пригодный исходный текст; он может остаться неполным, что является известным ограничением. Пустой результат учитывается как техническая ошибка. Обычные транспортные повторы внутри post сохраняются. Эмбеддинги не добавлены; реранкер по умолчанию выключен.

## Кандидат hybrid-v1
Добавлен hybrid.py: USE_HYBRID=1 включает эмбеддинги через EMB_MODEL и общий прокси. Индекс и векторы вопросов вычисляются при запуске пакетами по 16, только в памяти. Бюджет подготовки до 120 секунд с резервом на генерацию; при любой ошибке — исходный словарный поиск. USE_HYBRID=0 отключает этап. Реранкер по умолчанию выключен. Реальное качество эмбеддингов пока не измерено.

## Кандидат anchored-v1
Рабочий гибрид теперь сохраняет первые TOP_K словарных источников и добавляет до двух смысловых альтернатив после основного контекста. Итог до TOP_K+4 с оговорками, с прежним пределом 40 000 символов. Векторизация и бюджет те же. Это отдельная экспериментальная сборка; лучший наблюдаемый результат пока context-v1=53.028, hybrid-v1=49.348 по сообщению пользователя.

## hierarchy-v1
Добавлен hierarchy.py: USE_HIERARCHY=1 по умолчанию выбирает целостный материал явно определенного продукта и до четырех справочных разделов. При неоднозначности — словарный поиск. До двух продуктов, бюджет полных документов29тыс.символов, общая упаковка40тыс. USE_HYBRID по умолчанию теперь0. Промпт и обработка ответа как у context-v1; гипотеза качества проверяется отдельным архивом dist/energytool-hierarchy-v1.zip.
