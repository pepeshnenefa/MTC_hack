# МТС EnergyTool — минимальный пример сабмита

Это **учебный пример**, не готовое конкурсное решение. Он демонстрирует, как обратиться к LLM, эмбеддеру и реранкеру через API платформы, но не строит полноценный RAG. Поиск сделан намеренно простым: берёт **только первые 420 символов** каждого документа, выбирает не более 4 кандидатов и передаёт модели короткий контекст. Для качественного решения участники должны самостоятельно реализовать извлечение и разбиение документов, поиск релевантных фрагментов, обработку диалогов и проверку фактов.

## Что в ZIP

- `solution.py` — точка входа, которую запускает платформа;
- `requirements.txt` — зависимость `httpx`;
- `README.md` — эта инструкция.

Не кладите в ZIP API-ключи, вопросы платформы или базу знаний: платформа передаёт их в контейнер сама.

## Файлы и результат

В контейнере код читает `DATA_DIR/questions.csv` (`id,question`) и `DATA_DIR/knowledge-base.zip` (Markdown и TXT). Для совместимости поддерживаются также имена `train.csv`, `knowledge_base.zip` и `kb.zip`.

На выходе создаётся `submission.csv` в рабочем каталоге. Колонки — `id,answer`; скрипт сохраняет исходные ID, экранирует поля двойными кавычками и удаляет переносы строк внутри ответов.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL` (или `BASE_URL`, `OPENAI_BASE_URL`) | Адрес OpenAI-совместимого API |
| `LLM_API_KEY` (или `OPENAI_API_KEY`) | Ключ доступа к LLM |
| `EMBEDDER_API_KEY`, `RERANKER_API_KEY` | Отдельные ключи при их наличии; иначе используется LLM-ключ |
| `LLM_MODEL` (или `GEN_MODEL`, `OPENAI_MODEL`) | Модель генерации |
| `EMB_MODEL` | Модель эмбеддингов |
| `RERANKER_MODEL` | Модель реранжирования |
| `TOP_K` | Максимальное число исходных кандидатов; **в учебном примере дополнительно ограничено 4** |
| `RERANKER_TOP_N` | Сколько фрагментов брать после реранкера |
| `MAX_TOKENS` | Предел генерации на один ответ; значение платформы не обрезается до 384 |
| `TEMPERATURE` | Температура генерации |
| `MAX_WORKERS` | Число параллельно обрабатываемых вопросов |
| `CHUNKER` | В этом примере `common` означает обрезку по границе строки |
| `DATA_DIR` | Папка с файлами задачи, по умолчанию `data` |
| `PYTHONPATH` | Стандартная переменная Python, применяется автоматически |

### Примеры API-вызовов

- `POST /embeddings` → `{"model": EMB_MODEL, "input": ["текст"]}`
- `POST /rerank` → `{"model": RERANKER_MODEL, "query": "вопрос", "documents": ["текст 1", "текст 2"], "top_n": RERANKER_TOP_N}`
- `POST /chat/completions` → `{"model": LLM_MODEL, "messages": [{"role": "user", "content": "вопрос"}], "max_tokens": MAX_TOKENS}`

Реализация использует переменные окружения и не содержит ключей или hardcoded-адресов API.

**Оценка**: количество баллов у этого примера заранее не гарантировано; на платформе зависит от реальных ответов моделей и проверочных данных.
